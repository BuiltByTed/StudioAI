# Studio AI — initial Homeframe deployment

Studio AI is live with a React interface built on Homeframe. The product name,
sign-in, navigation, document title and installed-app metadata are Studio AI.
The mobile sidebar has no close-menu row; header navigation, backdrop, Escape and
link selection provide dismissal. Upstream attribution and license notices remain.

## Release identity and migration

- Repository: BuiltByTed/StudioAI, default branch `homeframe`.
- Application/server source: `16b1fbe290e5b78ead28aa8aadb23a13f57bb5be`.
- Promoted artifact: `20261019231018-212ac5c7`, built once and tested before promotion.
- Backend: existing Open WebUI 0.12.3, unchanged and not restarted.
- Database: no schema migration required; existing Alembic revision retained.
  Consistent online SQLite backup, integrity and record counts verified before
  and after cutover. Existing uploads remain in place.
- Browser migration: account-scoped drafts preserve text, attachments and tools;
  existing session/preferences remain compatible. Temporary drafts are not stored.
  Installed identity, scope, start URL and `/sw.js` remain stable.
- Homeframe: exact vendored 0.1.18-studio.1 compatibility package, source patch,
  license and provenance included. Fixes a reproduced iOS Safari keyboard-pan bug.

The reverse proxy switched gracefully while the original backend continued
serving requests. Across the final switch, 100 sampled HTTP requests returned 200
and an existing Socket.IO WebSocket remained connected and exchanged its heartbeat.
The backend PID and OpenCode installer checksum were unchanged. This is measured
continuity during the deployment window, not a general uptime guarantee.

Public verification found Cloudflare injecting scripts into otherwise valid HTML.
Homeframe correctly rejected the changed bytes during atomic precaching. A scoped
`no-transform` response policy now preserves the exact artifact through the edge;
the public service worker subsequently activated. No application CSP exception or
disabled cache-integrity verification was used. The deployment runbook and
`npm run test:deployment` cover this regression.

## Performance

Five cold and five warm Chromium runs per frontend used the same isolated backend
and a 1440×980 viewport. Cold runs used fresh contexts; warm runs revisited the
same route. Service workers were blocked to measure the frontend rather than an
existing shell cache. Timing ended at the visible editable composer.

| Frontend | Cold median (range), ms | Warm median (range), ms | Median requests until composer |
| --- | --- | --- | --- |
| Upstream 0.12.3 | 1040 (995–1052) | 444 (415–454) | 222 |
| Studio AI final artifact | 169 (143–300) | 128 (78–145) | 17 |

These are local browser measurements, not internet response times or model
generation benchmarks. Rich editors and Markdown/math rendering are loaded on
demand. Image generation/edit samples establish functionality, not a distribution.

## Explicit limitations

The [48-route inventory](ROUTE_INVENTORY.md) is a coverage map, not a claim of
complete upstream feature parity. Channels and app integrations are disabled in
this deployment and their UI is not migrated. Simultaneous multi-model comparison,
realtime voice calls and collaborative rich-note editing are not implemented.
Notes uses Markdown; chat selects one model; dictation and read-aloud are separate
controls. Existing server data and upstream source remain available.

Not every administrative setting was mutated. External OAuth providers, live
scheduled execution and physical microphone/speech-provider behavior remain
unverified. Native keyboard/PWA evidence comes from Apple simulators and native
desktop browsers, not physical iPhones. VoiceOver, third-party keyboards and iPad
split view are not certified. These gaps do not silently count as passed checks.

KaTeX was updated to 0.18.2. Remaining image-tool advisories concern Homeframe's
build-time `sharp` dependency processing trusted checked-in branding, not the
dependency-free production proxy. See the [dependency review](PROGRESS.md#dependency-review).

## Reproduction and rollback

```sh
cd homeframe-ui
npm ci
npm run check
npm run test:e2e
STUDIO_TEST_URL=https://your-studio.example npm run test:deployment
```

Use the exact artifact's `dist` directory for deployment verification, or set
`STUDIO_TEST_DIST`. A later rebuild receives its own build identity.

Follow the [deployment runbook](../../homeframe-ui/deploy/README.md) for immutable
release directories, same-identity worker rollback and graceful proxy switching.
Previous assets and the original backend target remain available for rollback.
Do not clear users' browser data or restart the backend to publish frontend assets.
